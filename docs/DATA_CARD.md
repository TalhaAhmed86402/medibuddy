# Data card

- **Origin:** fully synthetic, generated by `medibuddy_bench/gen/` (seed 1 for `dev`). No real patients, hospitals, or records. Hospital names are invented
  (name stems + generic suffixes); districts are real Seoul gu / four Suwon gu with approximate centroids for distance.
- **Real-world grounding (rules only):** referral requirement for tertiary hospitals and its exceptions, the 6-month NHI rule, numbers 119 / 1339 / 1330
  (Invest Korea guidance; public). HIRA open data inspired the hospital-index fields but is not included.
- **World window:** 2026-11-30 … 2027-06-25; holidays 2026-12-25, 2027-01-01, 2027-03-01, 2027-05-05, 2027-06-06.
- **Sizes (dev):** 288 scenarios; world hash `05bdb4da14d0353f`; per-task hashes in `data/dev/manifest.json`.
- **Languages:** English (patient), Korean (doctor; template-generated, 213 distinct phrasebook rows reviewable in `data/review/korean_phrasebook.csv`).
- **Known limits:** templated Korean; textbook-only triage; no dialects, no accents/ASR noise, no images; one country; simplified rules.
- **Sensitive-content handling:** health words appear only as fictional scenario content. T7 bait values (ARC number `990101-1234567`) are fake.
- **Splits:** `dev` public; `test` built by the organiser with a secret seed (never commit it); `mini` for smoke tests.
- **Leakage controls:** public view contains no gold; tested in `tests/test_benchmark.py`.


## Synthetic vs real (important)
All dev distributions (hospital counts per tier, language shares, interpreter shares, hours, prices) are **invented** in
`gen/hospitals.py` and carry no information about Korea. Plan: calibrate the distributions from real files (Ministry of Justice
resident statistics for patient languages; HIRA / data.go.kr district hospital files for hospital counts, tiers, hours and any
language field), keep hospital names fictional. `scripts/import_real_data.py` summarises such files; it has NOT been run on
real files yet.
